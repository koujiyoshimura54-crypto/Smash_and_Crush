## 2. 補間方法
表生成時のみ単調3次Hermite補間を使用。アンカー間の増分/Levelを割線傾きd、区間幅hとし、内部アンカーの接線傾きは隣接割線の加重調和平均を使った。重みはw1=2*h_next+h_prev、w2=h_next+2*h_prev。
端点Lv50の傾きは28,000（既存Lv49=222,000→Lv50=250,000の差）、Lv200は250,000,000（暫定延長と一致）。各Levelで補間した値を1,000単位に四捨五入。丸め後も全Thresholdの厳密増加とアンカー完全一致を検証した。

複雑な補間はRuntimeに持ち込んでいない。実装の正本は数値リテラル表。[生成パラメーター](interpolation.json)にアンカー・接線傾きを保存。中間値は仮バランスで、育成所要時間の最終調整済みを意味しない。

## 5–7. Lv201以降の暫定ルール・上限・数値安全性
**暫定**：Lv201〜10,000は `5,000,000,000 + (Level - 200) * 250,000,000`。
一定+250M/Level。Lv200付近の増分と連続的につながり、指数増加を使わない。
- Lv199=4,750,222,000
- Lv200=5,000,000,000
- Lv201=5,250,000,000
- Lv202=5,500,000,000
- Lv10,000=2,455,000,000,000（2.455T）

監査前の共通LevelRequirementsにはLv10,000のハード上限がなかった。10,000はRebirth将来テーブルにも登場する値であり、既存の上限制御が完成していたとは扱わない。今回はユーザー指定の上限Lv10,000をMaxLevelとして実装した。
CalculateLevelは1〜10,000の範囲を二分探索し、大きなStrengthでも有限回（最大14回）で終了する。Level上限に達してもStrengthは制限しない。
GetRequiredStrengthのLevel引数は1〜10,000に制限し、10001以上を問い合わせた場合もLv10,000のThresholdを返す。HUD上限時は進捗100%とし、同じ閾値によるゼロ除算を避ける。

Luau numberは64bit double。[Roblox公式Numbers](https://create.roblox.com/docs/luau/numbers)。最大Threshold2.455Tは2^53=9,007,199,254,740,992以内であり、すべて整数として正確に保持できる。整数1の増減、Attribute/JSONの往復、全Level境界を実行時に確認した。浮動小数の任意小数をすべて誤差ゼロで扱えるという意味ではない。
1e308と+InfinityでもLevel計算が終了し10,000を返す。NaN/負数はLv1を返す。Strength付与側の有限数検証は既存のまま。
